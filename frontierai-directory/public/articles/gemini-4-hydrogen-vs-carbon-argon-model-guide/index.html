Gemini 4 Hydrogen vs Carbon and Argon: which model should you use?

Gemini 4 Hydrogen changes Google's price-performance map. Independent tests show when to choose Hydrogen, Argon, Carbon, or keep Gemini 3.8 Flash.

Models covered: Gemini 4 Hydrogen, Gemini 4 Carbon, Gemini 4 Argon, Gemini 3.8 Flash

Hydrogen is a new execution tier, not a cheaper Carbon

Gemini 4 Hydrogen gives Google a generally available model between Gemini 3.8 Flash and the heavier Gemini 4 frontier tiers. It costs $1.50 per million input tokens and $7.50 per million output tokens, accepts text, images, audio, video, and PDFs, and uses a unified 1,048,576-token input-output window. Google positions it for everyday coding and agent execution, while Carbon remains the maximum-capability route and Argon the long-horizon workhorse. That product description is useful, but the practical choice depends more on effort setting and total task cost than on the family name.

Independent Artificial Analysis results make the distinction clearer. Hydrogen scores 27 at low effort, 41 at medium, 51 at the default high setting, and 54 at xhigh on Intelligence Index v5.0.1. The same evaluator scores Carbon at 60 and Argon at 50 under its current methodology. Hydrogen can therefore edge past Argon on this composite at high or xhigh, but it does not replace Carbon's higher ceiling. It also does not deliver one stable capability level: moving from low to xhigh changes the score by 27 points, effectively spanning several model classes behind one API name.

Google's launch tables report large gains over Gemini 3.8 Flash in coding, tool recovery, multimodal knowledge work, and factual discipline. Those comparisons are vendor-reported, even when they use public benchmark names. The Artificial Analysis score, token use, time, and cost figures are independently measured in a common harness. Neither evidence source predicts every private workflow, but together they support a narrow conclusion: Hydrogen is a credible new default candidate for agent execution, not automatic permission to migrate every Gemini workload.

Reasoning effort determines the real price-performance result

The $1.50/$7.50 list price is flat across the full context window, and implicit cache reads cost $0.075 per million tokens. That is simpler than long-context surcharges, but output pricing includes thinking tokens. Artificial Analysis measured average Intelligence Index task costs of about $0.29 at low, $0.80 at medium, $1.87 at high, and $3.16 at xhigh. The list price never changes; the bill changes because the model generates progressively more reasoning tokens. At xhigh, the evaluator classified Hydrogen as very verbose and measured roughly 304 million output tokens across its index run.

That makes high the sensible first production test for difficult agent work, not xhigh. High scores 51 independently, three points below xhigh, while costing roughly 41% less per evaluated task. Medium is the stronger candidate for routine worker agents: its score falls to 41, but the measured task cost drops to $0.80 and average evaluation time to 3.7 minutes. Low reaches $0.29 per task and 1.3 minutes, but its score of 27 means it should be treated as a bounded high-volume tier rather than a cheap version of frontier reasoning.

Caching helps only when prompts actually repeat. Hydrogen supports implicit caching with a 95% discount but not explicit cache creation, so applications cannot assume every long system prompt will receive the cache rate. Log cache-hit tokens, thinking and answer tokens separately. A nominally cheaper model that rereads a large repository, retries failed tools, or produces excessive reasoning can lose its advantage at task level. The correct optimization target is accepted completion cost, including retries and reviewer time, not the two numbers printed on a pricing page.

Choose Carbon for the ceiling, Hydrogen for throughput, and Argon cautiously

Carbon is now available to all paying Gemini API developers, removing the catalog's previous access objection. Its introductory $2/$10 price lasts through November 30 before rising to $4/$20. Artificial Analysis scores Carbon at 60, six points above Hydrogen xhigh. Use that premium where deeper exploration can materially change the answer: difficult architecture, stubborn multi-system debugging, scientific analysis, or security work with explicit authorization and review. Google says Carbon spends more tokens testing hypotheses and verifying edge cases; that is a feature on consequential work and waste on routine execution.

Hydrogen fits the larger middle: repository issue resolution, test-and-fix loops, multimodal document processing, interactive tool use, and parallel worker or verifier agents. Its synchronous output defaults to 65,536 tokens, with background or continuation-based long decode available up to the remaining unified context. That capability is unusually large, but it should not become a target. Long output increases cost and review burden, and a million-token unified window means input, reasoning, function calls, and final output compete for the same budget.

Argon now occupies an awkward position. Its current introductory price is $2/$10, higher than Hydrogen, and its independent composite score of 50 is one point below Hydrogen high. Google still recommends Argon for advanced long-horizon work with lower token use than Carbon, so existing Argon workloads should be evaluated rather than blindly moved. If Hydrogen matches acceptance quality with lower latency or cost, migrate. If Argon's behavior is more stable on long plans, retain it. When both Carbon and Argon rise to $4/$20 on December 1 while Hydrogen remains $1.50/$7.50, Argon will need workload-specific evidence to justify the gap.

Run a four-route evaluation before changing production traffic

Build a small evaluation from completed work rather than benchmark prompts. Include straightforward coding changes, cross-file bugs, tool failures, long multimodal inputs, ambiguous requirements, and tasks that previously needed escalation. Compare the current route with Hydrogen medium and high. Add Carbon only to the hard slice and Hydrogen xhigh only where high fails. If Gemini 3.8 Flash already meets the acceptance bar for extraction, classification, or latency-sensitive jobs, keep it as a control; a newer model is not automatically a cheaper model for simple work.

Measure accepted completion rate, omitted requirements, test pass rate, unsupported claims, retries, wall-clock time, cache hits, input tokens, thinking-plus-output tokens, and human review minutes. Use identical tools and task budgets where possible. Google reports that Hydrogen finishes some workloads faster and uses fewer tokens than 3.8 Flash, but those are vendor observations from selected workloads. Your own end-to-end measurements decide whether the gain survives a different repository, tool harness, data mix, and definition of success.

A minimal routing policy is enough. Send bounded, machine-checkable work to Hydrogen medium. Use Hydrogen high for normal coding and agent tasks that need stronger reasoning. Escalate failed or high-consequence work to Carbon, with xhigh tested as an intermediate route only if it saves money without reducing acceptance. Retain Argon or 3.8 Flash only where owned evidence shows a better operational result. This avoids both fashionable migration and needless model sprawl: three active routes are useful only when each owns a measurable class of work.

  • Independently measured: Hydrogen scores 27, 41, 51, and 54 from low through xhigh on Artificial Analysis Intelligence Index v5.0.1.
  • Vendor-reported: Google's coding, safety, multimodal, Agent Arena, MKA, and partner-workload gains.
  • Default trial: Hydrogen medium for bounded workers and high for everyday coding agents.
  • Escalation: Carbon for the hardest accepted-value tasks; test xhigh before adding it permanently.
